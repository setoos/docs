---
title: Reporting Tools
description: The four MCP tools for call logs, usage, post-call analysis and transcripts
---

Four tools, all read-only. They sit in one group because the workflow they serve starts
from a call list: find the calls, then read the verdict or the words.

Group name for `?tools=`: **`reporting`**

<Callout type="warning">
  Two of these need `transcripts:read`, which is the permission with the widest privacy
  reach in the platform. See [the privacy note](#a-word-on-transcripts) below before
  granting it.
</Callout>

## list_call_logs

Lists completed and in-progress calls. Filter by agent, campaign, status, direction
and date range.

**Permission:** `calls:read` · **Destructive:** no

The Call Logs page in the dashboard shows more than an AI assistant receives. This is
what each call returns through MCP:

| Available through MCP | Field |
| :--- | :--- |
| Call id | `sessionId` |
| Status | `status`, e.g. answered, missed, busy, failed |
| Channel and direction | `channel`, `direction` (inbound or outbound) |
| Agent | `agentId`, `agentName` |
| Campaign | `campaignId`, when the call was part of one |
| From / To | `fromNumber`, `toNumber`, `customerNumber` |
| Duration | `durationSec`, plus billed duration `billDurationSec` |
| Start and end time | `startedAt`, `endedAt`, `createdAt` |
| Why the call ended | `hangupCause` |

| Not available through MCP | Why |
| :--- | :--- |
| Per-call cost | Kept off the call list. For spend, use [`list_usage_records`](#list_usage_records), which reports totals, average cost per call and spend per agent. |
| Recording | A link to audio of a real person. It never reaches an AI client. |
| Provider (Plivo, Twilio, etc.) | Telephony internals an assistant cannot act on. |
| Workflow | Not included in the call log response. |
| What was said | Not in the list. Use [`get_call_transcript`](#get_call_transcript) for one call, which needs `transcripts:read`. |

```
Show me yesterday's calls.
How many calls failed this week?
How long was the last call to +91XXXXXXXXXX?
```

## list_usage_records

Reports usage and spend for a date range: total spent, average cost per call, call
counts, talk time, and the breakdown by agent and by component (LLM, TTS, STT,
platform).

**Permission:** `usage:read` · **Destructive:** no

These are the same figures as the tiles and the Usage by Component chart on your
dashboard home screen, so an assistant and the dashboard agree.

```
What have I spent this month?
Which agent is costing me the most?
How many calls did we make last month?
Which agent handled the most talk time in October?
```

Two things it does not include:

- **Your wallet balance.** That needs `wallet:read` and comes from
  `get_wallet_balance`. Spend is what has gone out; balance is what is left.
- **Per-vendor wholesale cost.** The component breakdown shows what you were charged,
  not what each provider charges us.

<Callout type="info">
  Spend is reported per currency, as a list. If you have switched billing currency at
  some point, historical spend exists in both and the amounts must not be added
  together.
</Callout>

## analyze_calls

Returns calls with the post-call analysis already computed for each — intent, lead
quality and similar, rather than raw dialogue.

**Permission:** `transcripts:read` · **Destructive:** no

This is the tool for questions about what calls *meant* across many of them.

```
Which calls last week looked like qualified leads?
Summarise what customers were asking about yesterday.
```

## get_call_transcript

The full transcript of one call — what the customer and the agent each said.

**Permission:** `transcripts:read` · **Destructive:** no

```
Show me the transcript of my last call.
What exactly did the customer on that failed call say?
```

<Callout type="info">
  Recordings are never exposed. There is no tool that returns a recording URL, and the
  field is filtered out of every response regardless of permissions.
</Callout>

## A word on transcripts

`transcripts:read` is flagged on the consent screen, and it is worth a moment's thought
even though it only reads.

A transcript is what a real customer actually said. Granting this permission means those
conversations leave 20X and enter whichever AI assistant you connected, where they are
processed under that provider's terms, not ours.

That may be exactly what you want — call analysis in a chat window is genuinely useful.
But it is a different decision from letting an assistant see how many calls you made,
and the consent screen keeps the two apart for that reason.

If you want call reporting without that reach, grant `calls:read` and `usage:read` and
leave `transcripts:read` off. `list_call_logs` and `list_usage_records` keep working.
